# Shared parts library

One builder per real-world part, used by every scene and by the tractor. A flywheel is a flywheel
wherever it appears: same profile, same starter ring gear, sized by its spec.

## Where things live

| Layer | Path | What |
| --- | --- | --- |
| Primitives | `src/geometry/index.ts` | `box`, `cylinder`, `tube`, `lathe`, `extrude`, `extrudeTwisted`, `gear`, `ringGear`, `cam`, `helixSpring`, `pipe`, `csg`, `merge`, `xform`, `mat4` |
| Primitive parts | `src/geometry/parts.ts` | `tyre`, `rim`, `bevelGear`/`bevelPair`, `splineShaft`, `sprocket`/`sprocketRadius`, `chainLink`, `loopPath` + `beltBand` (belts), `hexBolt`, `torus`, `loft` |
| **Parts library** | `src/parts/lib/<domain>.ts` | real machine parts, parametric, built from the two layers above |

## Rules

1. **Reuse before you build.** Before writing a builder, look in the three layers above. If a part exists, call it. If it is nearly right, add a spec option to it. Do not fork it.
2. **Worker-safe.** Library files import only `three`, `@/geometry*`, `@/physics/*` and other library files: no React, no DOM, no scene modules. Scenes import the library, never the reverse.
3. **Parametric, with the reference size as the default.** Take one spec object with defaults that reproduce the scene the part came from. That scene must look the same after the move unless it was wrong (see 6).
4. **Document the local frame** in the builder's comment: which axis, where the origin is, which way it faces.
5. **Solids stay closed and outward-facing**, since section caps need them. The geometry tests check this, so keep them passing.
6. **Correct while consolidating.** When parts of one kind differ, the library version is the right one: an engine flywheel always has its ring gear, and a piston always has rings and a gudgeon pin. A part that is genuinely different stays different: a baler flywheel has no ring gear, and a flex plate is not a flywheel. In that case give it its own builder, or an option.
7. **Moving code:** move the builder into the library and change the scene to call it. Keep the scene's exported names working by re-exporting them, so other importers do not break.

## Checks for every change

- `npx tsc --noEmit -p .` must pass, and so must the scene's own tests: `npx vitest run src/modules/<module>/<scene>`.
- Load each scene you touched headless against the dev server on `localhost:5173`. Use `node <scratchpad>/sweep.mjs <outDir> <module/scene> …` and look at the screenshot.
- Do not commit; the user handles git.
